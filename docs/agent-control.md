# Agent control: instruction and enforcement

**Instruction artifact — [docs/agents/manual-verification.md](agents/manual-verification.md).** `CLAUDE.md` is loaded into every session in this repo and carries the trigger inline, so the agent reaches the document on its own: when `/implement` has finished an issue and its test suite passes, but at least one acceptance criterion genuinely needs human access (credentials, an external dashboard, hardware, a billing-enabled service, an interactive browser check), the agent follows the handoff instead of closing the issue. Its completion criterion is the `## Done when` checklist, verifiable from the issue alone: open and labeled `ready-for-human` with `ready-for-agent` removed, exactly one `## Manual verification required` section, a separate handoff comment, and no credential values anywhere. It must **not** trigger when every criterion is agent-verifiable — a unit test, a script, a read-only API call — in which case the normal completion path stands and no `ready-for-human` label or checklist is added at all.

**Enforcement artifact — [.claude/hooks/block-github-final-actions.mjs](../.claude/hooks/block-github-final-actions.mjs).** A `PreToolUse` hook registered in `.claude/settings.json` inspects every `Bash` command before it runs and exits 2 — denying the call outright, not warning — on the pull-request merge and issue-close subcommands of `gh`. Merging a pull request and closing an issue are irreversible final judgements that stay human-only; the human runs them from the prompt with `!` when they decide to. An instruction alone is insufficient because it depends on the agent reading, remembering, and correctly applying the document under context pressure, and this repo has already seen that fail: issue #4 was closed prematurely, which is what commit `05b5243` was written to correct. The hook needs no cooperation from the model, so the same lapse now produces a blocked command instead of a closed issue — and deliberately nothing points at it from `CLAUDE.md`, because enforcement that depended on the agent reading an instruction would not be enforcement. Its known limits, accepted in exchange for staying small: it matches the Bash command string, so it will conservatively block a command that merely contains the forbidden text (including prose about it), and alternate paths to the same GitHub actions, such as `gh api`, are outside its current scope.
